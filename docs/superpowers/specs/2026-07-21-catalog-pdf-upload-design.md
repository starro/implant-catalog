# 새 카탈로그 등록 — PDF 드래그앤드롭 업로드

- 작성일: 2026-07-21
- 상태: 설계 승인됨
- 대상: `data-pipeline` (관리 UI 모달 + 업로드 API)

## 1. 배경과 문제

카탈로그 원본이 사내 NAS(`\\172.30.1.8`)에 브랜드별로 정리돼 있으나, 수집 잡이 도는 개발서버(58.229.105.3)는 NAS 와 **네트워크가 분리돼 있어 도달할 수 없다**(단일 공인망 NIC, 172.30.1.x 로 가는 경로 없음). 따라서 서버가 NAS 를 직접 마운트하는 방식은 인프라 변경 없이는 불가능하다.

수집 엔진(`sources/catalog_pdf.py`)은 이미 **로컬 파일 경로**를 지원한다(`Path(url).exists()` 분기). 부족한 것은 사용자 PC 의 PDF 를 서버로 올리는 통로다. 그래서 관리 UI 의 "새 카탈로그 등록" 모달에 **브라우저 드래그앤드롭 업로드**를 붙여, 사용자가 PC 에서 PDF 를 떨구면 서버에 저장하고 그 경로로 소스를 등록한다.

## 2. 목표 / 비목표

**목표**
- 새 카탈로그 등록 모달에 PDF 드래그앤드롭 업로드를 추가한다.
- 업로드된 파일을 서버의 `data/catalog/<브랜드>/` 아래 브랜드별로 정리해 저장한다.
- 업로드 후 서버 경로를 등록 폼의 주소 칸에 채운다. 등록·수집 로직은 바꾸지 않는다.
- 기존 URL 직접 입력 흐름과 한 화면에서 공존한다.

**비목표 (이번 범위 밖)**
- 폴더 일괄 업로드 / 여러 파일 동시 드롭.
- 업로드 진행률 바.
- 고아 파일(업로드 후 등록 취소분) 자동 청소.
- NAS 직접 연동(네트워크 인프라 변경 영역).

## 3. 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| 저장 위치 | `DATA_ROOT/catalog/` (모든 파이프라인 산출물이 모이는 `data/` 아래, gitignore·백업 대상) |
| 디렉토리 체계 | `data/catalog/<정규화 브랜드>/<원본이름>-<sha8>.pdf` |
| 브랜드 정규화 | `taxonomy.normalize_brand` 사용 (`Osstem` → `OSSTEM IMPLANT`), training·소스목록 그룹핑과 동일 표기 |
| 업로드 후 동작 | 경로만 채움 — 사용자가 폼 확인 후 `[등록]`/`[등록하고 바로 수집]` |
| 등록·수집 로직 | 변경 없음. 업로드가 만든 서버 경로를 기존 `url` 필드로 흘림 |
| 파일 형식 | `.pdf` + `application/pdf` 만 허용 |
| 최대 크기 | 100MB |
| 범위 | 단일 파일만 |

## 4. 동작 흐름

```
모달에서 브랜드 입력(또는 기본값 확인)
  → PDF 를 모달에 드롭
  → POST /api/uploads (multipart: file + brand)
      → 서버가 .pdf/크기 검증 → data/catalog/<브랜드>/<이름>-<sha8>.pdf 저장
      → 절대경로 반환
  → 모달이 그 경로를 "카탈로그 PDF 주소 또는 파일 드롭" 칸에 채움
  → 브랜드/시리즈/메모 확인 후 [등록] 또는 [등록하고 바로 수집]
      → 기존 POST /api/sources 흐름 그대로 (url = 서버 경로)
```

수집 시 Dagster 잡이 `Path(url).exists()` 로 그 파일을 읽는다(기존 동작). 등록·수집·검수·내보내기 경로는 URL 카탈로그와 동일하다.

## 5. 저장 규칙

- 경로: `DATA_ROOT/catalog/<safe(normalize_brand(brand))>/<safe(stem)>-<sha8>.pdf`
  - `<sha8>` = 파일 내용 SHA-256 앞 8자.
  - `safe(...)` = `storage.safe_component` (경로 조작·이상 문자 차단).
  - 확장자는 항상 `.pdf` 로 강제.
- **중복 처리**: 같은 내용을 다시 올리면 `<이름>-<sha8>` 이 같아 **동일 경로**가 된다.
  - 파일이 이미 있으면 다시 쓰지 않고 그 경로를 반환한다(멱등).
  - 이어지는 `POST /api/sources` 가 같은 `url` 로 들어오면 기존 `duplicate_url` 409 로 자연히 걸린다.
  - 이름은 같고 내용이 다르면 `<sha8>` 이 달라 별개 파일이 된다.
- 반환값은 **절대경로**다. Dagster 잡의 작업 디렉토리와 무관하게 해석되도록 한다.

## 6. API

### `POST /api/uploads`

- 입력: `multipart/form-data`
  - `file`: PDF 파일 (필수)
  - `brand`: 브랜드 원문 문자열 (필수, 예 `Osstem`)
- 검증:
  - `brand` 가 비면 400 `invalid_request` "브랜드를 먼저 입력하세요".
  - 파일명이 `.pdf` 가 아니거나 content-type 이 `application/pdf` 가 아니면 400 `invalid_file` "PDF 파일만 업로드할 수 있습니다".
  - 크기가 100MB 초과면 400 `file_too_large` "파일이 너무 큽니다 (최대 100MB)".
- 성공: `{ok:true, data:{path, filename, brand}}` — `path` 는 저장된 절대경로, `filename` 은 표시용 원본 이름, `brand` 는 정규화된 표기.
- 라우트는 `drheri_pipeline/ui/api/uploads.py` 에 두고 `app.create_app()` 의 routes 에 합류시킨다.

메서드는 GET/POST 규칙에 맞게 POST. 응답 봉투는 기존 `{ok,data,error}` 를 따른다. 인증은 두지 않는다(사내망 전용, 기존 API 와 동일).

## 7. 프론트엔드 (모달)

`web/src/routes/NewSource.svelte` 를 수정한다.

- **필드 순서 변경**: 브랜드 칸을 주소/드롭 영역 **위로** 올린다. 브랜드를 먼저 정하게 해 오배치를 막는다.
- **드롭 영역**: 모달 본문이 드롭 타깃이 된다. `dragover` 시 강조 테두리, `drop` 시 첫 PDF 를 업로드.
  - 목표 폴더 실시간 표시: "→ `OSSTEM IMPLANT/` 폴더로 업로드" (브랜드 입력값에 따라 갱신).
  - 파일 선택 버튼(`<input type=file accept=".pdf">`)도 함께 둬 드래그가 어려운 환경을 보조.
- **주소 칸 라벨**: "카탈로그 PDF 주소" → "카탈로그 PDF 주소 또는 파일 드롭". 타이핑 URL 입력은 그대로 동작.
- 업로드 성공 시: 반환 `path` 를 주소 칸에 넣고, 이름 칸이 비어 있으면 `filename` 으로 채운다.
- 업로드 중에는 등록 버튼을 비활성화하고 "업로드 중…" 표시. 실패 시 토스트(기존 `toast`).

디자인 토큰(미니멀 실무형)을 따르고 새 색·그림자를 도입하지 않는다.

## 8. 에러 처리

- 업로드 실패·형식 오류·용량 초과는 `{ok:false,error}` 로 반환하고 프론트가 토스트로 표시.
- 업로드는 성공했으나 사용자가 등록을 취소하면 파일은 `data/catalog/` 에 남는다(고아). 이번 범위에서는 수용하고, 축적이 문제되면 별도 청소 기능을 검토한다.
- 디스크 쓰기 실패는 500 `internal_error` (기존 핸들러).

## 9. 보안

- 저장 파일명은 `storage.safe_component` 로 정리해 `../` 등 경로 이탈을 차단한다. 최종 경로가 `DATA_ROOT/catalog/` 하위인지 확인 후 저장한다.
- 업로드 경로는 서버가 생성하므로 사용자가 임의 경로를 지정할 수 없다(주소 칸에 직접 타이핑하는 로컬 경로 문제는 기존과 동일, 이번 변경으로 확대되지 않음).

## 10. 테스트

- 업로드 API 단위 테스트(Starlette TestClient):
  - 정상 `.pdf` 업로드 → `data/catalog/<정규화 브랜드>/<이름>-<sha8>.pdf` 에 저장되고 절대경로 반환.
  - 동일 파일 재업로드 → 같은 경로 반환, 파일이 부풀지 않음(멱등).
  - 비-PDF 업로드 → 400 `invalid_file`.
  - `brand` 누락 → 400 `invalid_request`.
  - 100MB 초과 → 400 `file_too_large`.
  - 브랜드 정규화가 폴더명에 적용됨(`Osstem` → `OSSTEM IMPLANT`).
  - 파일명 경로 이탈 시도(`../evil.pdf`)가 `data/catalog/` 밖으로 나가지 않음.
- 업로드된 경로로 `POST /api/sources` 등록 시 기존 흐름이 동작하고, 같은 파일 재등록이 `duplicate_url` 로 걸리는지.

## 11. 배포

- `data-pipeline` 코드 갱신(로컬 → 개발서버 tar/scp, 기존 배포 방식). 프론트는 로컬(Node 24) 빌드 후 `web/dist` 업로드.
- 서버에 `data/catalog/` 는 최초 업로드 시 자동 생성(부모 디렉토리 `mkdir -p`).
- UI 서비스(`drheri-ui`) 재기동으로 반영.
